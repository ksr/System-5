# CPU card Rev D: theory of operation

CPU Rev D is the 2026 CPU card for the 36-pin bus. It keeps what the 2005 card did for the processor (the CDP1802, a 4K boot EPROM at F000-FFFF, the boot remap and -VMA) and drops what it did for the 1861: no ribbon to an IO card, no state codes or DMA OUT for video. In their place it listens to the bus for its run mode, so another card can reset, pause, load and step the machine with the CPU card in. Read [cpu-card.md](cpu-card.md) first: this chapter covers only what is new.

- Board status: **drawn and routed, not ordered, not built.** Two layers, 5.50 × 4.00 in (139.7 × 101.6 mm). `pcb-check --tests` passed at elf `9c0e767` (2026-11-22: no failures, 0 warnings), after the boot reset was added. It needs the bus Rev D's 36-pin slots ([bus-board-rev-d.md](bus-board-rev-d.md)) and does not fit the 2009 backplane.
- KiCad: `hardware/cpu/kicad/rev-d/`, generated by `gen/build.sh` from `gen/netlist.py` (the circuit), `gen/make_board.py`, `gen/route.py` and `gen/silk.py`. The redrawn schematic is `schematic/cpu-rev-d-schematic.pdf`.
- The full record, decision by decision: `hardware/cpu/kicad/rev-d/DESIGN.md`.

## What changed from Rev A, and why

| Rev A (2005) | Rev D | Why |
|---|---|---|
| 30-pin bus | 36-pin bus: -EF1-3, -DMAIN, SC0, -PAUSE as well | debug control and four flag lines ([bus.md](bus.md), "The 36-pin extension") |
| crystal, about 1.76 MHz | 4 MHz oscillator ÷ 2 = **2 MHz**, or an external clock | the old rate was for the 1861, which is gone |
| two 74LS20 run latches and a 74LS123 RUN pulse, driven by pulses | none: CLEAR follows -RESET and WAIT follows -PAUSE | -RESET and -PAUSE are levels on the bus, driven by any card |
| CM1232 with a watchdog | DS1813, no watchdog | the watchdog is fed by TPA, which stops in PAUSE, in LOAD and with the clock stepped |
| 74LS374 high-address latch | 74HCT373 | timing finding T1: the 374 latched on the wrong edge of TPA |
| window and VMA-mode jumpers (SV2, SV4, SV5) | none: always Boot/REMAP, EPROM at F000-FFFF | Ken, 2026-10-30 |
| boot map after every reset | the LOADED flag decides what a reset boots | LOAD → RESET → RUN runs a program from RAM, as on a COSMAC ELF |
| reset button only | a boot reset is a state of the bus | a front panel needs no cable to this card |

## Clock

X1 (4 MHz) clocks U4A, wired as a divider; its output, CLK_INT, is 2 MHz. The external clock comes in on J2 pin 1, EXT_CLK, held low by R2 when nothing is connected, and goes through a Schmitt inverter (U7A) to CLK_EXT; its polarity does not matter. **JP1 CLK** joins one of them to the 1802's CLOCK pin: INT (the end nearer the top edge) or EXT. The 1802's XTAL pin is open. The 1802 is static, so a debug board (BUSDRV-C, on a 6-way ribbon to J2) can run it slowly or step it edge by edge.

## Run control

There are no latches. Two Schmitt inverters in series take each bus line to the 1802:

- **CLEAR** follows **-RESET** (U7, through RST_H).
- **WAIT** follows **-PAUSE** (U7, through PAUSE_H).

So the four 1802 modes come straight off the bus: reset (-RESET low), run (both high), pause (-PAUSE low), load (both low). Any card may pull these lines, because they are open collector; RN1 here and RN2 on the bus board pull them up. U10, a DS1813 on -RESET, holds the line low at power-up and for 150 ms after whatever pulled it lets go. A released reset simply runs: Rev A needed a one-shot RUN pulse, and Rev D does not.

**SW1 RESET/RUN** grounds SW_RST in RESET (the lever up, towards the top edge as drawn). U12 holds SW_RST low at power-up and for 150 ms after SW1 returns to RUN. While SW_RST is low, U11A pulls -RESET and U11B pulls -DMAIN, unless the machine is paused. That is a **boot reset** (below). With -PAUSE low the switch pulls -RESET alone, which gives LOAD mode.

## The boot EPROM, the boot map and LOADED

U2 latches the high address byte while TPA is high, and so has it before TPA falls (finding T1 is gone). The EPROM U3 takes A0-A7 from the bus and LA8-LA11 from the latch; its data pins are on the bus, and its !OE is -MRD.

**The boot map** works as on Rev A as built ([cpu-card.md](cpu-card.md), "The boot EPROM and its remap"). CLEAR clears the boot flip-flop U4B, so its inverted output BOOT_PEND is high. The first rising edge of LA15 sets it. The gates are:

```
BOOTMAP_L  = NAND(BOOT_PEND, NOT_LOADED)     U5A
WIN_L      = NAND(LA12, LA13, LA14, LA15)    U6A   (F000-FFFF)
-VMA       = NAND(BOOTMAP_L, WIN_L)          U5B   (high while the EPROM answers)
ROM_SEL_L  = NOT -VMA                        U5C   (the EPROM's !CE)
```

While the map is on, the EPROM answers at every address and -VMA keeps the memory cards off. After the first fetch with A15 high, it answers at F000-FFFF only. Only this card drives -VMA, and it drives it push-pull.

**LOADED** (U8A) decides what a reset boots. LOAD mode sets it (LOAD_L = NAND(RST_H, PAUSE_H), U5D, on its preset). A boot reset clears it:

```
BOOT_L = NAND(RST_H, DMAIN_H, WAIT)          U6B
```

That is -RESET low and -DMAIN low while -PAUSE is high. While LOADED is set, NOT_LOADED holds the boot map off, so after a LOAD the sequence RESET → RUN starts the program loaded at 0000. The EPROM still answers at F000, so a loaded program can call HBIOS.

| What is done | LOADED | The next run starts in |
|---|---|---|
| power-on, SW1, or any boot reset (front panel RESET, the IO panel's RESET button, the bus driver's `MODE:4#`) | cleared | the EPROM: HBIOS |
| LOAD mode (-RESET and -PAUSE low) | set | RAM at 0000 |
| a plain reset (-RESET alone) | unchanged | whichever ran before |
| PAUSE alone | unchanged | |

One trap: leaving PAUSE by switching RUN off before LOAD passes through LOAD mode and sets the flag. The START FROM RAM LED shows it; SW1 clears it.

## DMA IN, and the interlock

System-5 makes DMA requests only in LOAD mode ([bus.md](bus.md)). The card enforces this, because -DMAIN also marks a boot reset:

```
ARM_L     = NAND(PAUSE_H, DMAIN_N)           U11D, R10   (paused, and -DMAIN high)
DMA_ARMED : cleared while -PAUSE is high, preset by ARM_L    U8B
DMA_IN    = NAND(DMAIN_H, DMA_ARMED)         U11C, R9    (the 1802's DMA IN, pin 38)
```

A low -DMAIN reaches the 1802 only in pause, and only once the line has been high since the pause began; a boot reset still held as LOAD is switched on (it takes about a microsecond to let go) would otherwise write a byte at 0000. So a loading card starts its request after LOAD mode begins, and drops it before clock 7 of the DMA cycle, using SC0 ([bus.md](bus.md), "Loading"). DMA OUT is not used.

## Flags

Each 1802 flag input has its own 2×4 block: JP2 for EF1 through JP5 for EF4. The rows are the bus lines -EF1, -EF2, -EF3 and -EF; a shunt across a row puts that line on the block's input. RN2 holds an input with no shunt high, which reads as no flag. The emulator sets EF1 = -EF1, EF2 = -EF2, EF3 = -EF and EF4 empty. That suits the 2005 IO card, whose keyboard flag reaches only -EF and which HBIOS reads on EF3. With a 36-pin keyboard card, put the flag on -EF3 and set JP4 to the -EF3 row.

## Bus lines driven

As on Rev A, the 1802's D0-D7, A0-A7, TPA, TPB, -MRD, -MRW, Q and N0-N2 go to the bus unbuffered. -VMA is push-pull (U5B). SC0 is buffered by U9D and U9E. -RESET and -DMAIN are pulled only by open-drain outputs (U10, U11).

## Connectors, jumpers, switch and LEDs

| Item | Where | What |
|---|---|---|
| J1 BUS | left edge | the 36 positions, counted from GND ([bus.md](bus.md)); every pin is named on the silkscreen |
| J2 DEBUG | the top-front corner | 1 EXT CLK, 2 GND, 3 CLOCK, 4 SC0, 5 SC1, 6 GND |
| JP1 CLK | top edge, between X1 and J2 | INT / EXT |
| JP2-JP5 | bottom edge | EF1-EF4 |
| SW1 | front edge | RESET (lever up) / RUN |

The LEDs are on the front edge, labelled by function: **PWR**; **Q** (Q high); **PAUSE** (WAIT low); **RESET** (CLEAR low); **ROM** (the EPROM selected); **START / FROM / RAM** (LOADED set, so a reset will start in RAM). PWR goes to GND; Q, PAUSE, RESET and ROM sink into their signals. The RAM LED is sourced from U8A's Q output, so NOT_LOADED, which gates the boot map, carries no LED current.

## Firmware

The EPROM holds HBIOS. The card is drawn so the chips already burned move across: the machine runs HBIOS v1.0.6 (`firmware/hbios/v1.0.6/`) in a 2732 at F000. Nothing in HBIOS needs changing for Rev D.

## Testing

- `python3 -m s5emu --hw --cpu-rev D` (from `software/s5emu`) runs the card from its netlist, `reports/netlist.net`; add `--panel A` and `--front A` for the IO panel and the front panel. HBIOS boots and ELF/OS runs.
- `tests/test_hw.py`, class `CPURevD`, covers the boot map, LOAD → RESET → RUN, PAUSE, the RAM LED, the boot reset, the DMA interlock and the EF routing. `Boot.test_cpu_rev_d_boots_hbios_and_echoes_a_key` boots HBIOS on it. Both are the `tests =` line of the card's `pcb-check.ini`.
- `software/busdrv`: the `load` plan in the bus driver's simulator, and `busboard.py`, which runs the card in the bus Rev D's netlist.
- Timing at 2 MHz (`python3 -m s5emu.timing --cpu D 2`, `hardware/TIMING-REVIEW.md`, 2026-10-30): the card itself has margin (-VMA +608 ns, EPROM data +1825 ns). The tightest path is the IDE card's INP into RAM (T6, +15 ns).

## Not yet proven on hardware

None of it: the card is not built. In particular: that the 74HC03 pulls -RESET under the DS1813's 0.4 V with every card's load on the line; SW1's direction (RESET with the lever up is drawn, not checked on a part); the 4.00 in card in the card guides; the DMA request's timing on a real 1802; and 2 MHz with the real cards, where T6 has little margin.
